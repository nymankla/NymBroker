# NymBroker.Endpoint.Http

`HttpEndPoint` — a **send-only** HTTP / webhook endpoint (plain `IEndPoint`, `Mode => WriteOnly` always; no listener). Decisions from #77: receiving webhooks is a sample + docs, not a package (no ASP.NET Core reference anywhere in the library); permanent 4xx failures are *not* mapped to dead-letter by Core — they throw like any other failure; the client comes from `IHttpClientFactory` (`Microsoft.Extensions.Http`, the only extra dependency).

- **Registration**: `AddHttpEndPoint(name, settings, configureClient?)` registers a named client `"NymBroker.Http." + name` with `Timeout = settings.Timeout`; `configureClient` gets the `IHttpClientBuilder` (users add auth/proxy handlers there). The endpoint is a keyed singleton holding one client from the factory — the factory's handler rotation still applies to the handler pipeline.
- **Request** (`HttpRequestFactory`, pure and unit-tested): the bytes are parsed once with `JsonDocument`; an object with a `message` property is an envelope → headers `X-NymBroker-Message-Id`, `-Message-Type`, `-Correlation-Id`, `Idempotency-Key` (= id), content type `application/json`, and with `BodyFormat.Payload` only the raw `message` JSON is sent. Anything else (raw bytes from `PostRawAsync`) is sent unchanged, `application/octet-stream` unless it parses as JSON. User `Headers` go to request headers, falling back to content headers.
- **Signature**: `X-NymBroker-Signature: t=<unix s>,v1=<lowercase hex HMAC-SHA256(secret, "<t>." + body)>` — Stripe-style, so a receiver can reject replays by timestamp. The timestamp comes from the injected `TimeProvider` (tests use a fixed one).
- **Retries** (Core `RetryPolicy`, exponential + jitter, max 30 s): `ShouldHandle = IsTransient` → `TimeoutException`, `HttpRequestException` without status (network/DNS/TLS), 408, 429, 5xx. `HttpClient.Timeout` surfaces as `TaskCanceledException`; when the caller's token is *not* cancelled it is rethrown as `TimeoutException` so it is retried and is not mistaken for shutdown. A `Retry-After` on 429/503 (delta or date, capped at 60 s) is awaited at the start of the next attempt, on top of the backoff. After the last attempt, or at once for other statuses, an `HttpRequestException` with `StatusCode` propagates — the broker then returns `Retry` for a route/topic destination, so the source queue retries and finally dead-letters (a 400 uses up the source's retry limit; documented).
- **Logging**: `OnRetry` logs Warning with the attempt and the exception message (status code + reason) — never the body or header values (they may hold secrets). The final exception is logged by the broker / caller, not here.
- **Health**: without `HealthCheckUrl` → `Healthy()` and no request (the target URL is never called just to check health); with it → `HealthCheckResult.FromProbeAsync` GET in `HealthCheckAsync`, 2xx = healthy.
- `PostBatchAsync`: the default (sequential `PostAsync`); a JSON-array batch mode is out of scope.
- Config: `HttpBodyFormat` carries `[JsonConverter(JsonStringEnumConverter<>)]` because Core's config reader has no enum converter (`"bodyFormat": "Payload"` must work).

Tests: `HttpEndPointTests` always run — a stub `HttpMessageHandler` records requests and scripts responses (no server, no env var). `samples/NymBroker.WebhookSample -- --demo` is the real Kestrel round trip (signing → verification → durable inbox → idempotent receiver → input transformer).
