# NymBroker.Endpoint.AwsSqs

`AwsSqsEndPoint` — Amazon SQS, standard and FIFO queues. `AWSSDK.SQS` only (v4: request/response collections and value properties can be `null`). Pull-based: its own long-polling loop on `Task.Run` with a linked CTS, not `LeasedQueueListener` (SQS's visibility timeout is the lease; there is no table to finalize).

- **Loop**: `ReceiveMessage` (`WaitTimeSeconds` 20, up to 10 messages, attributes `nymbroker-encoding` + `ApproximateReceiveCount`) wrapped in a `RetryPolicy` (exponential 1–30 s, jitter, unlimited, `OnRetry` logs Error). The batch is handled with `Parallel.ForAsync` (`MaxConcurrentCalls`, default 1), each message through `EndpointHandler.InvokeAsync`, then **settled per batch**: `DeleteMessageBatch` for Completed, `ChangeMessageVisibilityBatch(RetryDelay)` for anything else. One call per outcome per batch instead of one per message — the price is that the visibility timeout must cover the whole batch (documented on `VisibilityTimeout`).
- **No native dead-lettering** (user decision, #75): SQS has no "dead-letter this message" call, so `UsesNativeDeadLetter => false`. The broker posts undecodable/expired messages and consumer failures to its own dead-letter endpoint and returns `Completed`; route-destination failures return `Retry` → visible again → the queue's **redrive policy** (`maxReceiveCount`) moves repeat failures to the SQS DLQ. A `DeadLetter` result (only from a custom handler) is treated like `Retry` with a warning, never deleted — losing it would be worse.
- **Settlement uses `CancellationToken.None`**, so a message handled while stopping is still deleted. `StopListeningAsync` cancels, awaits the loop; messages of the current batch that weren't handled get `ChangeMessageVisibility(0)` so they come back at once instead of after the visibility timeout. A handler cancelled by the stop leaves its message to the visibility timeout. Settle failures → `LogError` (redelivered later), never thrown.
- **Encoding** (`SqsWireFormat`): an SQS body is a string of XML-safe characters. Valid UTF-8 without disallowed characters (all envelopes) is sent as text unchanged; anything else is Base64 with message attribute `nymbroker-encoding=base64`. Valid UTF-8 round-trips byte for byte through `string`.
- **FIFO** (queue name/URL ends in `.fifo`): group id = `MessageGroupId` ?? envelope `correlationId` ?? `"nymbroker"`; dedup id = envelope `id` ?? SHA-256 of the body. Parsed with a `Utf8JsonReader` over top-level properties only.
- **Batch send**: chunks of ≤ 10 entries and ≤ 256 KiB per request (conservative, valid on every SQS-compatible server). SQS accepts entries individually: on a failed entry the method throws, later chunks are not sent.
- **Client**: one `AmazonSQSClient` per endpoint (thread-safe), disposed with the endpoint. `ServiceUrl` (ElasticMQ/LocalStack) needs an `AuthenticationRegion` for signing — `Region` or `us-east-1`. `Credentials` is code-only (`[JsonIgnore]`); otherwise the SDK's default chain. `QueueName` is resolved to a URL on first use and cached (a failed lookup is retried next time).
- **Health**: `GetQueueAttributes` via `HealthCheckResult.FromProbeAsync` in `HealthCheckAsync`; unhealthy if the loop ended unexpectedly (`_loopFailed`).

Integration tests: `AwsSqsEndPointTests` (`NYMBROKER_SQS_URL=http://localhost:9324`, `./scripts/setup-sqs.ps1`) create a unique queue + DLQ with a redrive policy per test and delete them afterwards. ElasticMQ supports redrive, FIFO deduplication, `PurgeQueue` and the JSON protocol the v4 SDK uses.
